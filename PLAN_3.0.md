## 2. LSS: как это работает (проверено 20.10.2026)

1. **QtWebEngine 5.15 сайт не запускает.** UA: `Chrome/83.0.4103.122`,
   в консоли `Uncaught SyntaxError: Unexpected token '('` в `app-*.js`,
   окно пустое. **Решено:** панель переведена на WebView2 (pywebview) в
   отдельном процессе — UA `Chrome/155`, лист рисуется.
2. **CSP `frame-ancestors`** (заголовок ответа): `self`, owlbear, bridge.longstoryshort.app,
   `*.rolebaza.ru`, `mythforge.ru`, `dnd-online-alpha.vercel.app` и др.
   localhost в списке нет → обычный iframe невозможен, нужен либо верхнеуровневый
   показ страницы (как сейчас в `lss_embed`), либо регистрация домена у LSS.
3. **SDK отдаёт не всё.** Стабильно только `lss:roll`; экспериментально
   `lss:manifest`, `dnd:health` (HP current/max/temp), `lss:command`.
   КД, характеристик, навыков и инвентаря в протоколе нет.
   **Решение найдено:** страница листа сама ходит в
   `GET https://api.longstoryshort.app/character/<id>/` с заголовком
   `Authorization: Bearer <cookie lss-jwt>` и получает полный документ
   персонажа (`{_id, edition, data: "<json>"}`), где `data` — тот самый
   документ `jsonType: "character"`. Панель повторяет этот запрос из
   контекста страницы: HTTP 200, документ разбирается (проверено на
   персонаже «Ямал»: HP 56/56, КД 18, СИЛ 18 / ЛОВ 14 / ТЕЛ 18).
   Токен берём из куки `lss-jwt` (значение в кавычках — JSON-строка).
   В приложении токен не сохраняется и никуда не отправляется.
4. **PDF бесполезен для разбора.** В присланном `Ямал — LSS (1).pdf`
   есть текстовый слой, но шрифт без Unicode-карты: вместо букв — `����`.
   Извлечь характеристики надёжно нельзя. И не нужно: данные берём из API
   листа (п. 3). Скачивание JSON пользователю недоступно — больше не требуется.

Итог: **панель даёт и живые события (броски, HP), и полный документ
персонажа.** Отдельный импорт файла в базовом сценарии не нужен.

## 3. Целевая модель данных

```
saves/<сессия>/
    session.json                  # карты, текущая карта, плейлист
    maps/<map_id>/map.json        # картинка, сетка, геометрия
    maps/<map_id>/placements.json # какие токены стоят на карте и где (x, y)
    tokens/<token_id>/token.json  # имя, картинка, kind, hp/ac, размер
    tokens/<token_id>/actor.json  # карточка актёра (только kind=actor)
    tokens/<token_id>/sheet.json  # документ персонажа LSS (только kind=player)
    players/<slot_id>.json        # слот игрока: никто/ник, выданные token_id
```

Почему карточка/лист в папке токена, а не карты: перенос токена между картами
не должен копировать и расщеплять лист. Карта хранит только расстановку.

Инварианты (проверяются тестами):
* `kind=player` → есть `sheet.json`, `actor.json` не создаётся никогда;
* `kind=actor` → есть `actor.json`, `sheet.json` не создаётся никогда;
* id токена уникален в сессии и не меняется при переносе;
* смена `kind` запрещена (только удалить и создать заново) — иначе смешаются
  данные двух разных сущностей.

Слоты живут на сервере (это состояние живой сессии, как игроки):
`slots: {slot_id: {name, player_id|None, token_ids[]}}`. Мастер создаёт слоты
до и во время игры, игрок при входе занимает свободный; если свободных нет —
«Свободных слотов не осталось». Мастер назначает слоту токены и может
загрузить лист LSS в слот до подключения игрока.

## 5. Риски

* **LSS меняет сайт** — панель и парсинг могут отвалиться. Поэтому база
  данных — файл персонажа с версией формата, а панель только дополняет.
* **Неофициальные API** (`GET /character/:id`) использовать не будем без
  письменной договорённости: хрупко и против правил.
* **Миграция старого формата** — читаем `worlds/*/world.json`, пишем в `saves/`,
  старые папки не удаляем.
* **Вторая библиотека Chromium** (PyQt6) увеличит вес сборки; WebView2
  использует системный runtime.

iframe-мост.
