# Dice Lab — отдельный физический лоток

Прототип кубиков для последующей интеграции в стол. Это самостоятельное
PyQt-приложение: оно не подключено к серверу и не меняет `client/`.
Главное отличие от прежней анимации: **результат не задаётся заранее**.
Бросок задаёт только начальные условия, дальше Bullet считает падение,
отскоки, трение и столкновения. Число читается по фактическому повороту
после остановки.

![Dice Lab](../design/shot_dice_lab.png)

## Запуск

Из корня проекта:

```bash
python -m pip install -r dice_lab/requirements.txt
python -m dice_lab
```

На Windows проще всего открыть двойным щелчком `dice_lab/main.py` или
`dice_lab/start.bat`. Корневой `main.py` — это вход в виртуальный стол,
а не в Dice Lab; для кубиков используется отдельный файл внутри пакета.
Если `.py` открывается не Python, запускайте `start.bat`: он сам найдёт
`python` или `py` и оставит окно с ошибкой, если зависимости не стоят.

Нужны `PyQt5`, `panda3d` (в нём используется только `panda3d.bullet`,
без окна Panda3D) и `pygame` для звука. Из стола то же окно открывается
галочкой «Включить 3д дайсы»; без `panda3d` стол продолжает работать
с кнопочной панелью кубиков из 2.9.

## Что внутри

| Файл | Назначение |
| --- | --- |
| `geometry.py` | меши D4–D20, грани, нормали, подписи; без UI и физики |
| `physics.py` | Bullet-мир, лоток, броски, остановка, чтение результата |
| `render.py` | QPainter-рендер лотка, теней, граней и цифр |
| `rules.py` | обычный итог, преимущество и помеха без UI и физики |
| `audio.py` | звуки ударов и критов, равновероятные варианты, сетка бит |
| `assets/sounds/` | записи ударов и критических эффектов в MP3 |
| `app.py` | окно, режимы броска, набор, формула, история, переброс |
| `main.py` | отдельный вход для двойного щелчка; корневой `main.py` — стол |
| `stats.py` | статистика бросков без интерфейса |
| `../tests/test_dice_lab.py` | проверки физики, чтения, распределения и звука |

## Как получается результат

1. Для каждого кубика генерируются случайное положение, поворот, скорость
   и угловая скорость. Кубики выбрасываются сеткой от левой стены.
2. `BulletWorld` шагает с `dt = 1/120`: гравитация, трение, упругость,
   контакты с полом, бортами и друг другом.
3. Бросок считается завершённым, когда все тела почти неподвижны 0,3 с
   (или уснули). Таймаут — 12 с, вылет из лотка — ошибка.
4. Результат читается из итогового кватерниона:
   * у d4 — по вершине, ближайшей к вертикали;
   * у остальных — по грани с самым вертикальным нормальным вектором.
5. Если вторая грань/вершина ближе 16°, кубик считается нечитаемым
   (`COCKED`). Он не заменяется случайным числом: его можно перебросить
   отдельно, остальные остаются лежать.

Нигде нет функции «повернуть к выпавшему числу»: `target_for_value` из
старого прототипа в этом пакете отсутствует.

## Преимущество и помеха

В списке «Режим» есть три варианта:

* **Обычный бросок** — любые кубики, итог равен их сумме плюс модификатор;
* **Преимущество** — ровно два d20, берётся больший;
* **Помеха** — ровно два d20, берётся меньший.

При выборе преимущества или помехи набор сам становится `2d20`, а кнопки
количества и поле формулы блокируются: режим требует ровно два d20, чтобы
не смешивать его с другими кубиками. Модификатор остаётся доступным и
прибавляется уже к выбранному d20. При возврате в обычный режим
восстанавливается прежний набор.

Результат показывает оба кубика; выбранный обведён золотой рамкой. В
истории видно оба значения и выбор, например:

```text
2d20+5 [преимущество]  →  22   (8, 17; выбран 17)
```

Если один из d20 встал на ребро, он считается нечитаемым: итог не
показывается, а перебросить можно только этот кубик — второй остаётся
лежать. Правило выбора живёт в `rules.py` и не зависит от Bullet.

## Критические 1 и 20

Критический эффект включается только в двух случаях:

* обычный бросок ровно одного `d20` (модификатор разрешён);
* преимущество или помеха — там всегда два d20, и смотрится выбранный.

Если в наборе есть другие кубики (`d20+d6`) или в обычном режиме брошены
`2d20`, эффекта нет: это не проверка d20 по правилам 5e.

**Натуральная 1.** Фон темнеет в красный, камера нервно дрожит, по центру
экрана появляется большая красная `1`: она наплывом увеличивается, затем
растворяется. Играет `crit_fail.mp3` (d1).

**Натуральная 20.** Фон заливает золотое свечение, сверху летят конфети,
по центру выплывает большая золотая `20`: она наплывом уменьшается и
растворяется. Играет `crit_success.mp3` (d20).

![Критический успех](../design/shot_crit_success_full.png)

![Критический провал](../design/shot_crit_fail_full.png)

Эффекты рисует `render.py`, правило выбора — `critical_kind()` в
`rules.py`, звуки — `DiceAudio.play_critical()`.

### Варианты крита

Ведущие нули в именах записей — это всё та же натуральная 1: `1`, `01`,
`001`, `00001`.

Все записи крита равновероятны. Раньше редкие треки включались с шансом
2–30%, и за вечер можно было ни разу не услышать «фахх» или танец;
теперь выбор идёт равномерно по всему списку, а сработавшая запись
заменяет обычный `crit_fail.mp3` / `crit_success.mp3`, а не играет поверх.

| Запись | Шанс | Когда |
| --- | --- | --- |
| `crit_success.mp3` | 1/3 | натуральная 20 |
| `crit_success_20_30.mp3` | 1/3 | натуральная 20 |
| `crit_success_20_2.mp3` | 1/3 | натуральная 20, с танцем |
| `crit_fail.mp3` | 1/8 | натуральная 1 |
| `crit_fail_1_2.mp3`, `crit_fail_01_2.mp3` | по 1/8 | натуральная 1 |
| `crit_fail_1_10.mp3`, `crit_fail_01_10.mp3`, `crit_fail_001_10.mp3`, `crit_fail_00001_10.mp3`, `crit_fail_fahhh_10.mp3` | по 1/8 | натуральная 1 |

Гарантии от «сухой серии» больше не нужны: обычный трек не вытесняет
остальные, а выбор не запоминает предыдущий — подряд может выпасть одна
и та же запись, как и при честном кубике.

Особая анимация есть только у записи с танцем: цифра `20` живёт ровно
столько, сколько звучит трек (около 9,6 с), и танцует — подпрыгивает,
качается и разворачивается на каждом ударе. Сетка ударов считается из
самого трека в `detect_beats()`: окна по 10 мс, прирост громкости,
локальные максимумы. Без numpy и без заранее прописанного BPM; если
запись заменить, танец сам подстроится. На каждом бите от цифры
расходится золотое кольцо. Остальные записи крита играют с обычной
короткой анимацией успеха или провала.

Если для записи удары не нашлись, остаётся ровный грув с периодом
`SPECIAL_BEAT_SECONDS` (0,87 с — темп этого трека).

![Редкая 20 танцует на бите](../design/shot_crit_success_special_full.png)

Через пять секунд после старта трек ещё звучит — и цифра продолжает
качаться, а на каждом ударе летят новые конфети:

![Редкая 20 в конце трека](../design/shot_crit_success_special_late.png)

## Звук ударов и критов

Звук ударов привязан к физике, а не к таймеру: `step()` сравнивает скорость тела
до и после шага Bullet и возвращает скачок скорости как удар. Поэтому
слышно именно момент касания, а сила удара зависит от реальной скорости.

| Запись | Когда играет |
| --- | --- |
| `single_die.mp3` | одиночный удар по столу или борту |
| `dice_tumble.mp3` | старт броска 2–10 кубиков |
| `dice_fall.mp3` | сильный удар или старт большой горсти (>10) |
| `dice_floor.mp3` | тяжёлое падение горсти на пол |
| `crit_success.mp3` | натуральная 20 (обычный трек) |
| `crit_fail.mp3` | натуральная 1 (обычный трек) |
| `crit_success_20_2.mp3` | 20, шанс 1/3, танцующая анимация |
| `crit_success_20_30.mp3` | 20, шанс 1/3 |
| `crit_fail_*_2.mp3` | 1, по 1/8 каждая |
| `crit_fail_*_10.mp3` | 1, по 1/8 каждая |

Удар одного кубика не дублируется чаще раза в 0,06 с; за один шаг
проигрывается не больше трёх самых сильных ударов, чтобы горсть не
превращалась в шум. Громкость удара — от 0,22 до 0,9 и умножается на
общую громкость из ползунка. Флажок «Звук» выключает и старт броска,
и удары, и критические записи.

Если аудиоустройства нет, `DiceAudio` тихо отключается: бросок, физика
и результат продолжают работать. `SDL_AUDIODRIVER=dummy` удобен для
проверок без звуковой карты.

### D4

У классического d4 число напечатано у вершины. Кубик лежит на грани
(три нижние вершины на полу), а результат — верхняя вершина. В тестах
проверяется наклон верхней вершины после остановки.

## Цифры на гранях

Цифры рисуются не поверх экрана, а в плоскости грани: базис из рёбер
грани, клип по её контуру, поворот вместе с кубиком. Для d6 верх цифры
направлен на середину ребра, для остальных — на первую вершину; у d4
каждое число у своей вершины развёрнуто от центра грани. У 6 и 9 есть
подчёркивание, чтобы их нельзя было спутать. Только d10 печатает `0`
вместо `10`; на d12 и d20 значение 10 остаётся двузначным.

## Проверки

```bash
python tests/test_dice_lab.py
```

Тест делает настоящие броски, включая 1000 d20 для распределения, и
проверяет:

* все грани/вершины имеют правильные значения;
* у d10 напечатан `0` вместо `10`, а у d12/d20 — именно `10`;
* d4 после остановки лежит на грани, а не на вершине;
* результаты всегда в диапазоне кубика;
* за 1000 d20 выпали все 20 граней, хи-квадрат ниже критического
  значения при p = 0.001, нечитаемых меньше 5%;
* бросок шести разных кубиков завершается без вылетов и зависаний;
* преимущество берёт больший d20, помеха — меньший, модификатор
  прибавляется после выбора, а один d20 в этих режимах отклоняется;
* крит срабатывает на 1/20 только для 1d20 и преимущества/помехи, но не
  для смешанного набора или обычных 2d20;
* все записи ударов и критов на месте, выбор записи, громкость и редкая
  реплика работают, а выключенный звук не играет;
* все записи крита равновероятны: у провала 1/8 на каждую из восьми,
  у успеха 1/3 на каждую из трёх; выбор заменяет обычный крит;
* сетка бит находится по громкости записи, а поза танцующей 20
  подпрыгивает на бите и успокаивается между ударами;
* эффект конфети включается на 20 и снимается перед новым броском.

Статистика вручную:

```bash
python -m dice_lab.stats --sides 20 --rolls 2000 --seed 7
```

Снимок прогона по 1000 бросков на каждый кубик: [STATS.md](STATS.md).

`seed` нужен только для воспроизводимости проверки; в приложении
используется `random.SystemRandom`, а начальные условия не связаны с
нужным результатом.

## Интеграция в стол

Пакет специально разделён на слои:

* `DicePhysics.throw(...)`, `step()`, `readings()` не знают о PyQt;
* `render.py` не знает, откуда взялись позы;
* `app.py` — окно и сигнал для стола.

Стол уже использует пакет:

1. `DiceLabWindow.rolled` отдаёт `formula`, `total`, `mode` и `breakdown`
   после остановки кубиков.
2. `MainWindow` открывает окно кнопкой «Бросить кубики» или иконкой D20
   (галочка «Включить 3д дайсы» в стартовом окне) и отправляет этот
   результат всем участникам через `ROLL_DICE`.
3. `COCKED` остаётся отдельным статусом: нечитаемый бросок в чат не уходит.
4. Кнопочная панель из 2.9 остаётся режимом по умолчанию; встроенная
   предрасчитанная анимация `client/dice_window.py` больше не используется.

Старый архив с прежней предрасчитанной физикой лежит рядом:
`../../vtt_dnd_physics_2026-10-20`. Он не используется этим пакетом.
